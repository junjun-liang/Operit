## 一、模块概述

### 1.1 设计定位

异常处理模块是 Operit AI Agent 的**错误处理基础设施**，通过定义语义清晰的自定义异常类，实现不同错误场景的分类处理、精细化错误提示和统一的错误恢复策略。

### 1.2 核心设计思想

| 设计理念 | 说明 |
|---------|------|
| **语义化异常** | 每种异常类对应特定错误场景，便于精准捕获和处理 |
| **携带上下文** | 异常携带 HTTP 状态码、错误响应体等上下文信息 |
| **协程友好** | `UserCancellationException` 继承 `CancellationException`，与 Kotlin 协程取消机制兼容 |
| **重试策略区分** | `NonRetriableException` 标识不可重试错误，避免无效重试 |
| **全局兜底** | `GlobalExceptionHandler` 捕获未处理异常，防止应用崩溃 |

### 1.3 异常体系总览

```
Throwable
├── Exception
│   ├── CancellationException
│   │   └── UserCancellationException          ← 用户主动取消
│   ├── IOException
│   │   └── NonRetriableException (x3)         ← 客户端错误（4xx）
│   ├── IllegalStateException
│   │   └── CloudEmbeddingException            ← Embedding 服务错误
│   ├── IllegalArgumentException
│   │   └── ToolParameterConversionException   ← 工具参数转换错误
│   ├── TtsException                           ← TTS 服务错误
│   ├── ConversionException                    ← 格式转换错误
│   ├── ColorQrException                       ← 二维码编解码错误
│   ├── TimeoutException                       ← 流操作超时
│   └── TakeCompletedException                 ← Stream take() 内部信号
│
└── Thread.UncaughtExceptionHandler
    └── GlobalExceptionHandler                 ← 全局未捕获异常处理
```

## 二、核心异常类详解

### 2.1 UserCancellationException

**文件路径**: `util/exceptions/UserCancellationException.kt`

```kotlin
class UserCancellationException(
    message: String,
    cause: Throwable? = null
) : CancellationException(message) {
    init {
        initCause(cause)
    }
}
```

**设计要点**：
- 继承 `CancellationException`（而非普通 `Exception`），与 Kotlin 协程取消机制深度兼容
- 协程中的 `CancellationException` 不会被 `try/catch` 的通用 `Exception` 捕获，避免误处理
- 通过 `initCause` 保留原始异常链，便于调试

**使用场景**：

```kotlin
// OpenAIProvider.kt - 检测到手动取消时抛出
if (isManuallyCancelled) {
    throw UserCancellationException("Request cancelled by user")
}

// 重试逻辑中显式检测
when {
    error is UserCancellationException -> throw error  // 直接重新抛出，不重试
    error is NonRetriableException -> throw error       // 不重试
    retryCount < maxRetries -> retry()                   // 可重试
    else -> throw error                                  // 重试耗尽
}
```

**适用模块**：OpenAIProvider、GeminiProvider、ClaudeProvider 等 LLM Provider

### 2.2 TtsException

**文件路径**: `api/voice/TtsException.kt`

```kotlin
class TtsException(
    message: String,
    val httpStatusCode: Int? = null,
    val errorBody: String? = null,
    cause: Throwable? = null
) : Exception(message, cause)
```

**设计要点**：
- 携带 `httpStatusCode` 和 `errorBody`，便于上层根据具体错误进行精细化提示
- 支持链式异常（`cause` 参数），保留原始错误信息

**使用场景**：

```kotlin
// OpenAIVoiceProvider.kt - TTS 请求失败
if (!response.isSuccessful) {
    throw TtsException(
        message = "TTS request failed",
        httpStatusCode = response.code,
        errorBody = response.body?.string()
    )
}

// UI 层捕获并展示
try {
    ttsProvider.speak(text)
} catch (e: TtsException) {
    showError("TTS 错误 (${e.httpStatusCode}): ${e.errorBody}")
}
```

**适用模块**：OpenAIVoiceProvider、OpenAIRealtimeVoiceProvider、OnnxVoiceProvider

### 2.7 NonRetriableException

**文件路径**: 各 LLM Provider 内部类

```kotlin
// OpenAIProvider.kt / GeminiProvider.kt / ClaudeProvider.kt
class NonRetriableException(
    message: String,
    cause: Throwable? = null
) : IOException(message, cause)
```

**设计要点**：
- 三个 Provider 各有一个同名的内部类
- 继承 `IOException`，便于被网络层的重试逻辑捕获
- 标识 4xx 客户端错误，通常不应重试

**使用场景**：

```kotlin
// 当响应码为 400-499 时抛出
when (response.code) {
    in 400..499 -> throw NonRetriableException("Client error: ${response.code}")
    in 500..599 -> throw IOException("Server error: ${response.code}")  // 可重试
}

// 重试逻辑中区分处理
retryWithBackoff {
    apiCall()
}.catch { error ->
    when {
        error is UserCancellationException -> throw error
        error is NonRetriableException -> throw error  // 不重试
        else -> throw error  // 其他错误由外层重试策略处理
    }
}
```

**适用模块**：OpenAIProvider、GeminiProvider、ClaudeProvider

## 三、全局异常处理

### 3.1 GlobalExceptionHandler

**文件路径**: `util/GlobalExceptionHandler.kt`

```kotlin
class GlobalExceptionHandler(private val context: Context) : Thread.UncaughtExceptionHandler {
    override fun uncaughtException(thread: Thread, ex: Throwable) {
        // 1. 记录异常堆栈到日志
        AppLogger.e("GlobalException", "Uncaught exception in thread ${thread.name}", ex)
        
        // 2. 保存崩溃信息到文件（用于后续上报）
        saveCrashReport(ex)
        
        // 3. 启动崩溃报告 Activity
        val intent = Intent(context, CrashReportActivity::class.java).apply {
            flags = Intent.FLAG_ACTIVITY_NEW_TASK
            putExtra("crash_stack", Log.getStackTraceString(ex))
        }
        context.startActivity(intent)
        
        // 4. 终止进程
        Process.killProcess(Process.myPid())
        exitProcess(1)
    }
}
```

**注册方式**：

```kotlin
// Application.onCreate()
Thread.setDefaultUncaughtExceptionHandler(GlobalExceptionHandler(this))
```

**设计要点**：
- 捕获所有线程的未处理异常
- 记录日志并保存崩溃报告
- 启动崩溃报告页面，给用户友好提示
- 终止进程避免进入不可预期状态

## 四、异常处理最佳实践

### 4.1 异常分类处理策略

```kotlin
suspend fun <T> safeApiCall(
    block: suspend () -> T
): Result<T> {
    return try {
        Result.success(block())
    } catch (e: UserCancellationException) {
        // 用户取消：静默处理，不记录错误
        Result.failure(e)
    } catch (e: NonRetriableException) {
        // 客户端错误：直接返回，不重试
        AppLogger.w("API", "Client error: ${e.message}")
        Result.failure(e)
    } catch (e: IOException) {
        // 网络错误：可重试
        AppLogger.e("API", "Network error", e)
        Result.failure(e)
    } catch (e: Exception) {
        // 其他错误：记录并返回
        AppLogger.e("API", "Unexpected error", e)
        Result.failure(e)
    }
}
```

### 4.2 重试策略与异常配合

```kotlin
suspend fun <T> retryWithExponentialBackoff(
    maxRetries: Int = 3,
    initialDelay: Duration = 1.seconds,
    block: suspend () -> T
): T {
    var currentDelay = initialDelay
    
    repeat(maxRetries) { attempt ->
        try {
            return block()
        } catch (e: UserCancellationException) {
            throw e  // 用户取消：立即终止
        } catch (e: NonRetriableException) {
            throw e  // 不可重试：立即终止
        } catch (e: Exception) {
            if (attempt == maxRetries - 1) throw e
            delay(currentDelay)
            currentDelay *= 2  // 指数退避
        }
    }
    
    throw IllegalStateException("Retry logic error")
}
```

### 4.3 异常转换与包装

```kotlin
// 底层异常 → 业务异常
fun mapToBusinessException(throwable: Throwable): AppException {
    return when (throwable) {
        is UserCancellationException -> AppException.Cancelled
        is TtsException -> AppException.TtsError(throwable.httpStatusCode, throwable.errorBody)
        is CloudEmbeddingException -> AppException.EmbeddingError(throwable.message)
        is IOException -> AppException.NetworkError
        else -> AppException.Unknown(throwable.message)
    }
}
```

### 4.4 协程中的异常处理

```kotlin
// 使用 SupervisorJob 隔离子协程异常
val scope = CoroutineScope(SupervisorJob() + Dispatchers.Main)

scope.launch {
    // 子协程 1：即使失败也不影响其他子协程
    launch {
        try {
            riskyOperation1()
        } catch (e: Exception) {
            handleError(e)
        }
    }
    
    // 子协程 2：正常执行
    launch {
        safeOperation2()
    }
}
```

## 六、设计亮点

1. **语义化异常体系**：每种异常对应特定错误场景，便于精准捕获和处理

2. **协程取消兼容**：`UserCancellationException` 继承 `CancellationException`，与 Kotlin 协程取消机制无缝集成

3. **上下文信息丰富**：`TtsException` 携带 HTTP 状态码和错误体，`ColorQrException` 覆盖编解码全生命周期

4. **重试策略友好**：`NonRetriableException` 标识不可重试错误，避免无效重试浪费资源

5. **全局兜底保护**：`GlobalExceptionHandler` 捕获未处理异常，记录日志并启动崩溃报告页面，防止应用直接崩溃

6. **内部异常隔离**：`ToolParameterConversionException` 和 `TakeCompletedException` 作为 `private` 内部类，不暴露实现细节

7. **异常链保留**：所有异常类都支持 `cause` 参数，保留原始异常信息，便于调试
