## 一、模块概述

### 1.1 设计定位

向量索引模块是 Operit AI Agent 的**语义搜索基础设施**，基于 HNSW（Hierarchical Navigable Small World）近似最近邻算法，为记忆库和文档检索提供高效的语义相似度搜索能力。

### 1.2 核心设计思想

| 设计理念 | 说明 |
|---------|------|
| **HNSW 近似搜索** | 使用 HNSW 算法在大量高维向量中快速找到最近邻，时间复杂度 O(log n) |
| **余弦相似度** | 使用 FLOAT_COSINE_DISTANCE 作为距离度量，适合文本语义相似度计算 |
| **维度分组** | 按向量维度分组管理索引，支持模型切换和多维度共存 |
| **持久化存储** | 索引通过 Java 序列化保存到文件，支持应用重启后快速恢复 |
| **泛型包装** | IndexItem 泛型设计，将业务对象（Memory/DocumentChunk）与向量解耦 |

## 二、核心组件详解

### 2.1 VectorIndexManager

`VectorIndexManager` 是向量索引的核心管理类，封装了 HNSW 索引的初始化、增删查、持久化等操作。

```kotlin
class VectorIndexManager<T : Item<Id, FloatArray>, Id : Any>(
    private val dimensions: Int,      // 向量维度
    private val maxElements: Int,     // 最大元素数
    private val indexFile: File? = null  // 索引文件（可选）
) {
    private var index: HnswIndex<Id, FloatArray, T, Float>? = null

    init { initIndex() }
}
```

**构造函数参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `dimensions` | `Int` | 向量维度，由 Embedding 模型决定（如 1536） |
| `maxElements` | `Int` | 索引最大容量，超过后自动扩容 |
| `indexFile` | `File?` | 索引持久化文件路径，null 则不持久化 |

#### 初始化索引

```kotlin
fun initIndex() {
    index = if (indexFile != null && indexFile.exists()) {
        try {
            // 尝试从文件加载已有索引
            ObjectInputStream(indexFile.inputStream()).use {
                it.readObject() as HnswIndex<Id, FloatArray, T, Float>
            }
        } catch (e: Exception) {
            // 加载失败则删除损坏文件并重建
            indexFile.delete()
            HnswIndex
                .newBuilder(dimensions, DistanceFunctions.FLOAT_COSINE_DISTANCE, maxElements)
                .withRemoveEnabled()
                .build()
        }
    } else {
        // 创建新索引
        HnswIndex
            .newBuilder(dimensions, DistanceFunctions.FLOAT_COSINE_DISTANCE, maxElements)
            .withRemoveEnabled()
            .build()
    }
}
```

**容错设计**：加载失败时自动删除损坏文件并重建新索引，避免应用崩溃。

#### 添加向量

```kotlin
fun addItem(item: T) {
    ensureCapacity(size() + 1)  // 确保容量足够
    index?.add(item)
}
```

#### 删除向量

```kotlin
fun removeItem(id: Id, version: Long = Long.MAX_VALUE): Boolean {
    return index?.remove(id, version) ?: false
}
```

**版本控制**：HNSW 支持乐观锁删除，传入 `Long.MAX_VALUE` 表示无条件删除。

#### 近似最近邻搜索

```kotlin
fun findNearest(query: FloatArray, k: Int): List<T> {
    return index?.findNearest(query, k)?.map { it.item() } ?: emptyList()
}
```

**参数说明**：
- `query`：查询向量（与索引向量同维度）
- `k`：返回最近邻的数量
- 返回：按相似度排序的 `IndexItem` 列表（最相似在前）

#### 容量管理

```kotlin
fun ensureCapacity(minCapacity: Int) {
    val current = index ?: return
    if (minCapacity > current.maxItemCount) {
        current.resize(minCapacity)  // 自动扩容
    }
}
```

#### 持久化

```kotlin
fun save() {
    if (indexFile != null && index != null) {
        try {
            indexFile.parentFile?.mkdirs()  // 确保父目录存在
            ObjectOutputStream(indexFile.outputStream()).use {
                it.writeObject(index)
            }
        } catch (e: IOException) {
            AppLogger.e("VectorIndexManager", "Failed to save index", e)
        }
    }
}
```

**序列化方式**：使用 Java 原生 `ObjectOutputStream` 序列化 HNSW 索引对象。

### 2.2 IndexItem

`IndexItem` 是 HNSW 索引的泛型包装器，将业务对象与向量关联。

```kotlin
data class IndexItem<Id : Any, T>(
    private val id: Id,              // 唯一标识
    private val vector: FloatArray,  // 向量数据
    private val version: Long = 0L,  // 版本号
    val value: T                     // 关联的业务对象引用
) : Item<Id, FloatArray> {

    override fun id(): Id = id
    override fun vector(): FloatArray = vector
    override fun dimensions(): Int = vector.size
    override fun version(): Long = version
}
```

**泛型参数**：

| 参数 | 说明 | 在 Operit 中的实际类型 |
|------|------|----------------------|
| `Id` | 索引项的唯一标识类型 | `Long`（Memory/Chunk 的 ID） |
| `T` | 关联的业务对象类型 | `Long`（存储原始对象的 ID） |

**设计意图**：
- `value` 字段存储原始对象的 ID（而非对象本身），避免内存占用过大
- 查询后通过 ID 反向查找数据库获取完整对象
- `equals` 和 `hashCode` 仅基于 `id`，确保同一对象不会被重复索引

## 三、HNSW 算法简介

### 3.1 什么是 HNSW

**HNSW（Hierarchical Navigable Small World）** 是一种基于图的近似最近邻搜索算法，由 Malkov 和 Yashunin 于 2016 年提出。

### 3.2 核心原理

```
┌─────────────────────────────────────────────────────────────────┐
│                    HNSW 分层图结构                                │
│                                                                 │
│  Layer 3 (最稀疏)                                               │
│       ●─────────●                                               │
│              │                                                  │
│  Layer 2      ●─────────●───────●                               │
│              /│\        │      /                                │
│  Layer 1    ●─●─●───────●─────●───●                             │
│            /│\│/│\     /│\   /│\  /                             │
│  Layer 0  ●─●─●─●─●───●─●─●─●─●─●─●  (最密集，包含所有节点)      │
│                                                                 │
│  搜索时从顶层开始，逐层向下，快速定位到目标区域                    │
└─────────────────────────────────────────────────────────────────┘
```

**特点**：
- **分层结构**：顶层稀疏（长距离连接），底层密集（短距离连接）
- **贪心搜索**：每层从入口点开始，贪心选择最近邻，直到局部最优
- **近似最优**：牺牲少量精度换取极大的性能提升
- **动态插入**：支持增量添加节点，无需重建整个索引

### 3.3 与精确搜索对比

| 特性 | 暴力搜索 | HNSW |
|------|---------|------|
| 时间复杂度 | O(n) | O(log n) |
| 空间复杂度 | O(n) | O(n × M) |
| 精度 | 100% | >95%（可调节） |
| 动态更新 | 容易 | 支持 |
| 适用规模 | 小规模（<1万） | 大规模（百万级） |

### 3.4 距离函数

Operit 使用 **余弦相似度**（Cosine Similarity）：

```kotlin
DistanceFunctions.FLOAT_COSINE_DISTANCE
```

余弦相似度衡量两个向量方向的夹角，适合文本语义相似度计算：
- 值域：[-1, 1]
- 1 表示完全相同方向（最相似）
- 0 表示正交（无关）
- -1 表示相反方向（最不相似）

## 四、在 Operit 中的应用场景

### 4.1 记忆语义搜索

**流程**：

```
用户输入查询文本
    │
    ├──► CloudEmbeddingService.generateEmbedding(text)
    │       └──► HTTP POST /v1/embeddings
    │               └──► 返回 FloatArray（如 1536 维）
    │
    ├──► MemoryRepository.getSemanticMemoryCandidatesFromIndex(queryEmbedding)
    │       └──► VectorIndexManager.findNearest(queryVector, availableCount)
    │               └──► 返回语义最相似的记忆 ID 列表
    │
    └──► 与关键词、标签、图传播结果融合（RRF 排序）
            └──► 返回最终排序的记忆列表
```

**索引文件**：`memory_hnsw_{profileId}_{dimension}.idx`

**重建索引**：

```kotlin
private fun rebuildMemoryVectorIndexForDimension(dimension: Int, excludedMemoryId: Long? = null): Int {
    val items = memoryBox.all
        .asSequence()
        .filter { memory -> excludedMemoryId == null || memory.id != excludedMemoryId }
        .mapNotNull { memory ->
            val itemDimension = memory.embedding?.vector?.size ?: return@mapNotNull null
            if (itemDimension != dimension) return@mapNotNull null
            createMemoryIndexItem(memory)
        }
        .toList()

    val indexFile = memoryIndexFileForDimension(dimension)
    deleteIndexFileIfExists(indexFile)
    if (items.isEmpty()) return 0

    val manager = VectorIndexManager<IndexItem<Long, Long>, Long>(
        dimensions = dimension,
        maxElements = items.size.coerceAtLeast(1),
        indexFile = indexFile
    )
    items.forEach { item -> manager.addItem(item) }
    manager.save()
    manager.close()
    return items.size
}
```

### 4.2 文档区块语义搜索

**流程**：

```
用户上传文档
    │
    ├──► 文档按段落分块（DocumentChunk）
    │
    ├──► 每个区块生成 Embedding
    │       └──► CloudEmbeddingService.generateEmbedding(chunk.text)
    │
    └──► 为每个文档重建区块向量索引
            └──► rebuildDocumentChunkIndex(memory)
```

**索引文件**：`doc_index_{profileId}_{memoryId}_{dimension}.hnsw`

**搜索**：

```kotlin
private fun getSemanticChunkCandidatesFromIndex(
    memory: Memory, 
    queryEmbedding: Embedding

    val manager = ensureDocumentChunkIndex(memory, queryEmbedding.vector.size) ?: return emptyList()
    val nearest = manager.findNearest(queryEmbedding.vector, availableCount)
    manager.close()
    // ... 转换为 DocumentChunk 列表
}
```

### 4.3 混合排序（RRF）

语义搜索结果与其他信号融合：

```
搜索结果融合
    │
    ├──► 语义搜索结果（向量相似度）
    │       └──► VectorIndexManager.findNearest()
    │
    ├──► 关键词匹配结果（BM25/TF-IDF）
    │       └──► 文本匹配分数
    │
    ├──► 标签匹配结果
    │       └──► 标签重合度
    │
    ├──► 反向包含结果
    │       └──► 查询被记忆内容包含
    │
    └──► 图传播结果
            └──► 知识图谱关联度
    │
    └──► RRF (Reciprocal Rank Fusion) 融合排序
            └──► score = Σ(1 / (k + rank_i))
```

## 五、Embedding 服务集成

### 5.1 CloudEmbeddingConfig

```kotlin
data class CloudEmbeddingConfig(
    val enabled: Boolean = false,
    val endpoint: String = "",      // 如 https://api.openai.com/v1
    val apiKey: String = "",
    val model: String = ""          // 如 text-embedding-3-small
) {
    fun isReady(): Boolean {
        return enabled && endpoint.isNotBlank() && apiKey.isNotBlank() && model.isNotBlank()
    }
}
```

### 5.2 CloudEmbeddingService

```kotlin
class CloudEmbeddingService(private val context: Context) {
    suspend fun generateEmbedding(config: CloudEmbeddingConfig, text: String): Embedding? {
        val requestBodyJson = JSONObject()
            .put("model", config.model)
            .put("input", text)
            .toString()

        val request = Request.Builder()
            .url("${config.endpoint}/embeddings")
            .post(requestBodyJson.toRequestBody("application/json".toMediaType()))
            .addHeader("Authorization", "Bearer ${config.apiKey}")
            .build()

        httpClient.newCall(request).execute().use { response ->
            return parseEmbedding(response.body?.string())
        }
    }
}
```

### 5.3 Embedding 数据模型

```kotlin
data class Embedding(val vector: FloatArray) {
    override fun equals(other: Any?): Boolean {
        other as Embedding
        return vector.contentEquals(other.vector)
    }
    override fun hashCode(): Int = vector.contentHashCode()
}
```

### 5.4 数据库转换器

```kotlin
class EmbeddingConverter : PropertyConverter<Embedding?, ByteArray?> {
    override fun convertToEntityProperty(databaseValue: ByteArray?): Embedding? {
        val buffer = ByteBuffer.wrap(databaseValue)
        val floatBuffer = buffer.asFloatBuffer()
        val floatArray = FloatArray(floatBuffer.remaining())
        floatBuffer.get(floatArray)
        return Embedding(floatArray)
    }

    override fun convertToDatabaseValue(entityProperty: Embedding?): ByteArray? {
        val vector = entityProperty.vector
        val buffer = ByteBuffer.allocate(vector.size * 4)  // 4 bytes per float
        val floatBuffer = buffer.asFloatBuffer()
        floatBuffer.put(vector)
        return buffer.array()
    }
}
```

**存储格式**：`FloatArray` → `ByteBuffer` → `ByteArray` → ObjectBox Blob 字段

## 六、使用方法

### 6.1 创建向量索引

```kotlin
// 定义索引文件
val indexFile = File(context.filesDir, "my_index.idx")

// 创建索引管理器（1536 维，最大 10000 条）

    dimensions = 1536,
    maxElements = 10000,
    indexFile = indexFile

```

### 6.2 添加向量

```kotlin
// 创建索引项
val item = IndexItem(
    id = 1L,
    vector = floatArrayOf(0.1f, 0.2f, 0.3f, /* ... 1536 维 */),
    version = System.currentTimeMillis(),
    value = 1L  // 关联的业务对象 ID
)

// 添加到索引
manager.addItem(item)

// 保存到文件
manager.save()
```

### 6.3 搜索最近邻

```kotlin
// 查询向量（同样 1536 维）
val queryVector = floatArrayOf(0.15f, 0.25f, 0.35f, /* ... */)

// 查找最近的 10 个邻居
val nearest = manager.findNearest(queryVector, k = 10)

// 遍历结果
nearest.forEach { item ->
    println("ID: ${item.id()}, Similarity: 相关")
    println("Value: ${item.value}")
}
```

### 6.4 删除向量

```kotlin
// 删除指定 ID 的向量
val removed = manager.removeItem(id = 1L)
if (removed) {
    manager.save()  // 保存更新后的索引

```

### 6.5 关闭索引

```kotlin
// 释放资源
manager.close()
```

## 八、设计亮点

1. **HNSW 高效搜索**：使用 HNSW 算法实现 O(log n) 的近似最近邻搜索，适合大规模向量检索

2. **余弦相似度**：使用 FLOAT_COSINE_DISTANCE，适合文本语义相似度计算

3. **维度分组**：按向量维度分组管理索引文件，支持模型切换和多维度共存

4. **自动容错**：索引文件损坏时自动删除重建，避免应用崩溃

5. **泛型设计**：`IndexItem<Id, T>` 泛型包装，与具体业务对象解耦

6. **持久化恢复**：通过 Java 序列化保存/加载索引，应用重启后快速恢复

7. **容量自动扩容**：`ensureCapacity()` 自动检测并扩容索引容量

8. **版本控制删除**：支持乐观锁删除，避免并发冲突

## 九、性能考量

| 场景 | 建议 |
|------|------|
| **索引构建** | 批量添加后统一 `save()`，避免频繁 IO |
| **搜索频率** | 搜索完成后及时 `close()` 释放资源 |
| **索引大小** | 单索引文件建议不超过 10 万条，过大时分片 |
| **维度选择** | 根据 Embedding 模型确定，常见 384/768/1536 维 |
| **内存占用** | HNSW 索引内存占用约为原始数据的 2-3 倍 |
