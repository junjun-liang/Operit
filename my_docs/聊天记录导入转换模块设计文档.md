# 聊天记录导入转换模块设计文档

## 1. 模块概述

`com.ai.assistance.operit.data.converter` 模块是 Operit AI 应用的**聊天记录导入转换系统**，负责将外部各种格式的聊天记录文件（JSON、Markdown、CSV 等）解析并转换为应用内部统一的 `ChatHistory` / `ChatMessage` 数据模型，实现跨平台聊天记录的无缝迁移。

---

## 2. 设计思路

### 2.1 核心设计原则

| 原则 | 说明 |
|------|------|
| **策略模式（Strategy Pattern）** | 每种外部格式对应一个独立的转换器，实现统一的 `ChatFormatConverter` 接口 |
| **自动格式检测** | 通过 `ChatFormatDetector` 自动识别文件格式，无需用户手动选择 |
| **容错与降级** | 解析失败时跳过单条消息/单个会话，不影响整体导入；异常信息通过 `ConversionException` 抛出 |
| **角色规范化** | 将各种外部角色名称统一映射为 `user` / `ai` 两种内部角色 |
| **时间戳兼容** | 支持秒级/毫秒级时间戳自动识别与转换 |

### 2.2 架构层次

```
┌─────────────────────────────────────────────────────────────┐
│                    ChatFormatDetector                        │
│              （自动识别文件格式，分发到对应转换器）              │
└─────────────────────────────────────────────────────────────┘
                              │
        ┌──────────┬──────────┼──────────┬──────────┐
        ▼          ▼          ▼          ▼          ▼
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ChatGPT   │ │ChatBox   │ │Generic   │ │Markdown  │ │ 其他...  │
│Converter │ │Converter │ │Json      │ │Converter │ │          │
└──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘
        │          │          │          │          │
        └──────────┴──────────┴──────────┴──────────┘
                              │
                              ▼
              ┌───────────────────────────┐
              │    ChatFormatConverter    │
              │      （统一接口）          │
              └───────────────────────────┘
                              │
                              ▼
              ┌───────────────────────────┐
              │  ChatHistory / ChatMessage │
              │      （内部数据模型）       │
              └───────────────────────────┘
```

### 3.3 ChatFormatDetector（格式检测器）

定义于 [ChatFormatDetector.kt](file:///Users/liangyingjie/Documents/my_agent_projects/Operit/app/src/main/java/com/ai/assistance/operit/data/converter/ChatFormatDetector.kt)

这是一个单例对象（`object`），负责自动识别文件内容的格式：

**检测优先级：**
1. **空白内容** → `UNKNOWN`
2. **Markdown 格式** → 检测 `<!-- chat-info:` / `<!-- msg:` 注释标记 或 `## User` / `## Assistant` 对话标题
3. **CSV 格式** → 检测包含 `timestamp` / `role` / `content` / `sender` 头的逗号分隔内容
4. **JSON 格式** → 进一步检测具体子类型：
   - `ChatFormat.CHATGPT`：包含 `mapping` + `current_node`
   - `ChatFormat.OPERIT`：包含 `id` + `title` + `messages` + `createdAt`
   - `ChatFormat.CLAUDE`：包含 `uuid` 或 `chat_messages`
   - `ChatFormat.GENERIC_JSON`：包含 `role` + `content` 的数组或对象
5. **默认** → `PLAIN_TEXT`

**扩展名辅助检测：**

```kotlin
fun detectFormatByExtension(fileName: String): ChatFormat?
```

| 扩展名 | 推测格式 |
|--------|----------|
| `.json` | `null`（需内容检测） |
| `.md` / `.markdown` | `MARKDOWN` |
| `.csv` | `CSV` |
| `.txt` | `PLAIN_TEXT` |
| `.html` / `.htm` | `UNKNOWN` |

|-------------|---------|
| `user` | `user` |
| `assistant` | `ai` |
| `system`（用户自定义） | `user` |
| `system`（默认） | 跳过 |

### 4.3 GenericJsonConverter

|---------|------|

| 对话数组 | `[{"title":"xxx","messages":[...]}, ...]` |
| 单个对话对象 | `{"title":"xxx","messages":[...]}` |

**容错设计：**
- 空数组返回空列表
- 无法解析的对象自动跳过（`mapNotNull`）
- 没有时间戳时使用递增时间戳（间隔 100ms）

### 4.4 MarkdownConverter

文件：[MarkdownConverter.kt](file:///Users/liangyingjie/Documents/my_agent_projects/Operit/app/src/main/java/com/ai/assistance/operit/data/converter/MarkdownConverter.kt)

**适用场景：** 导入 Markdown 格式的聊天记录文件。

**支持的格式特征：**

1. **HTML 注释标记（推荐）：**
   ```markdown
   <!-- chat-info: title=对话标题, created=2024-01-01 12:00:00 -->
   <!-- msg: role=user, model=gpt-4 -->
   用户消息内容
   <!-- msg: role=assistant -->
   AI 回复内容
   ```

2. **YAML Front Matter（兼容旧版）：**
   ```markdown
   ---
   title: 对话标题
   created: 2024-01-01 12:00:00
   ---
   ```

3. **标题式角色标记：**
   ```markdown
   ## User
   用户消息
   
   ## Assistant
   AI 回复
   ```

**解析策略：**
- 整个文件视为一个对话（不再通过 `---` 分割）
- 使用状态机逐行解析，维护 `currentRole` / `currentContent`
- `justStartedMessage` 标记用于跳过紧随注释后的装饰性 `## Role` 标题

**日期解析：** 支持多种格式（ISO、自定义 pattern）
```kotlin
private val dateFormatters = listOf(
```

## 5. 使用方法

### 5.1 基本使用流程

```kotlin
// 1. 检测文件格式
val format = ChatFormatDetector.detectFormat(fileContent)

// 2. 获取对应转换器
val converter = when (format) {
    ChatFormat.CHATGPT -> ChatGPTConverter()
    ChatFormat.CHATBOX -> ChatBoxConverter(context)
    ChatFormat.GENERIC_JSON -> GenericJsonConverter()
    ChatFormat.MARKDOWN -> MarkdownConverter(context)
    else -> throw ConversionException("Unsupported format")
}

// 3. 执行转换
val histories = converter.convert(fileContent)
```

### 5.2 结合文件扩展名检测

```kotlin
val formatByContent = ChatFormatDetector.detectFormat(content)
val formatByExtension = ChatFormatDetector.detectFormatByExtension(fileName)

// 如果内容检测为 UNKNOWN，可尝试使用扩展名辅助判断
val finalFormat = if (formatByContent == ChatFormat.UNKNOWN) {
    formatByExtension ?: ChatFormat.UNKNOWN
} else {
    formatByContent
}
```

### 5.3 错误处理

```kotlin
try {
    val histories = converter.convert(content)
    // 保存到数据库或展示给用户
} catch (e: ConversionException) {
    // 向用户显示友好的错误信息
    showError(e.message)
}
```

## 7. 扩展指南

### 7.1 添加新的导入格式

1. **在 `ChatFormat` 枚举中添加新格式：**
   ```kotlin
   enum class ChatFormat {
       // ... 现有格式
       NEW_FORMAT  // 新格式
   }
   ```

2. **创建转换器类，实现 `ChatFormatConverter`：**
   ```kotlin
   class NewFormatConverter : ChatFormatConverter {
       override fun convert(content: String): List<ChatHistory> {
           // 实现解析逻辑
       }
       
       override fun getSupportedFormat(): ChatFormat = ChatFormat.NEW_FORMAT
   }
   ```

3. **在 `ChatFormatDetector` 中添加检测逻辑：**
   ```kotlin
   private fun detectJsonObjectFormat(obj: JsonObject): ChatFormat {
       // ... 现有检测
       if (keys.contains("new_format_key")) {
           return ChatFormat.NEW_FORMAT
       }
       // ...
   }
   ```

4. **在使用处注册转换器：**
   ```kotlin
   val converter = when (format) {
       // ... 现有转换器
       ChatFormat.NEW_FORMAT -> NewFormatConverter()
   }
   ```

### 7.2 设计建议

- **保持单一职责：** 每个转换器只处理一种外部格式
- **充分容错：** 使用 `try-catch` 包裹单条消息/单个会话的解析，避免整体失败
- **角色统一：** 通过 `normalizeRole()` 将外部角色映射为 `user` / `ai`
- **时间戳兼容：** 处理秒级/毫秒级时间戳的自动识别
- **依赖注入：** 需要 `Context` 的转换器通过构造函数传入，便于获取字符串资源
